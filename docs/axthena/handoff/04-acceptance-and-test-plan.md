# Axthena proposed acceptance tests

Prepared 15 October 2026 for the design handoff. This is a proposed acceptance matrix, not a test execution report or permission to implement. It follows the current AX/ENG decisions, with AX-052 taking precedence over the earlier collection-date default, AX-038/ENG-035 replacing the original one-Idea limit, and ENG-026 selecting automatic creation after a completed no-selection identity decision. Badr's latest satisfaction with the graph is a review milestone; it does not establish production execution, performance, or resolution of every extraction-contract gap.

## Evidence and status vocabulary

All production acceptance tests below remain unrun. A retained diagnostic can support part of a test's expectation without satisfying its production acceptance gate.

**Release-required behaviour:** expectations traced to accepted AX/ENG invariants must hold in V1 unless Badr explicitly revises scope. **Proposed-contract tests:** parts marked C must first receive an approved contract and frozen expected result; the wording here does not select a schema, numerical mapping, interval convention, grouping algorithm or conflict-read policy. Where one row mixes them, the invariant is required and only the unresolved implementation/read-policy expectation is blocked.

| Marker | What it establishes |
|---|---|
| **D — retained diagnostic** | The harder fictional trial observed the stated behaviour under supplied inputs and its experimental contract. It does not establish real-source acquisition, actual candidate retrieval, insertion, clustering or production reads. |
| **P — offline projection** | The A-only graph projection was checked offline for integrity and fidelity. Its Cypher was inspected, not executed in Neo4j. |
| **S — stress finding** | The older model review identified a current-fixture defect, an in-memory counterexample, or an untested coverage case. These are diagnostic findings, not a passing production suite. |
| **U — pending acceptance** | Concrete expected behaviour follows an accepted invariant, but no production acceptance run exists. |
| **C — contract choice pending** | Some invariant is accepted, but an output contract, policy, boundary, or reference answer must be reviewed before scoring the unresolved part. Do not count this as an LLM failure or as solved. |

Evidence anchors: **D** = `Axthena-hard-trial-results-2026-10-15.md` and retained hard-trial packet; **P** = `Axthena-graph-review-guide-2026-10-15.md` and retained graph packet; **S** = `Axthena-model-stress-review-2026-10-14.md`. G01–G06 refer to the unscored `hard_contract_gaps.md`. AX/ENG IDs refer to the current authoritative context documents. Q numbers below refer to the newer graph guide unless explicitly identified as older stress queries.

The retained trial reported A/B/C agreement on 36 report records, 12 supplied identity tasks and 36 supplied comparisons each; 38 Ideas and 14 stock judgments each; 42/42, 48/48 and 52/52 exact quotations respectively; and 10/10 illustrative JSON reads each. No incorrect SAME label was observed on that comparison set. These are narrow observed denominators, not general accuracy estimates. The A-only reordered check matched 36/36 previously used meanings. HM03 and HM13 remain defensible borderline SAME cases for owner review. Preserve the frozen inputs, raw outputs, accepted alternatives and original scores unchanged.

## Recommended acceptance sequence

1. **Approve the semantic contract before scoring its gaps.** Review AT-02/03/04, G01–G06, HM03/HM13, program-facing qualification, full Event/Fact/Confirmation/dependency extraction, view/hold reads and interval conventions. Separate an accepted invariant from an unselected representation. A blocked case needs a recorded decision or explicit scope deferral, not an invented expected answer. Deferring a required V1 concept requires an explicit owner scope decision.
2. **Use a compact invariant suite.** Treat the 36 rows as scenario families, with small contrast pairs. Run deterministic checks on identities, evidence reconstruction, date eligibility, idempotence and retained outputs; use owner-reviewed semantic cases where automated equality is inadequate. The proposed gate is no unresolved material violation of an accepted invariant in this frozen packet. This is a release condition for that packet, not a statistical reliability guarantee.
3. **Run the requested 20-article source trial as the first OpenCode task, then build the bounded end-to-end slice before any later twelve-month collection.** It must challenge supplied assumptions: body fidelity, snapshot dates, source attribution, candidate retrieval, extraction, grouping, application and useful reads. Include one partial, one correction/uncertain-availability case and one meaningful non-merge. Preserve missing information rather than selecting only easy successful reports.
4. **Run the sequential local workflow and recovery gate.** Demonstrate retained-evidence reuse, partial retry, sequential identity reuse, repeat-ingestion/application consistency, restart/restore and exact evidence recovery. A projected JSON graph or supplied CREATE result cannot substitute for these behaviours.
5. **Accept useful reads with Badr.** Review stock/date evidence, the manual two-stock view, source expressions behind shared meaning, subsidiary/domain targeting, qualified forecasts, confirmation/hold and explanation of empty results. Full qualification must survive the human/program interface. Graph-review satisfaction is evidence for the review stage; this gate checks the specified application behaviour.
6. **Benchmark only after output correctness and workload targets are frozen.** Agree measurable local targets, source/period coverage expectations and budget scope. Report performance, storage and model costs as measurements with conditions; compare alternatives on the same evidence and accepted reads. No predictive-performance gate belongs to this data-focused V1.

Deferred coverage must remain visible: detailed quoted-judgment attribution, dedicated reasons/thought-process reuse, role classification, same-name legal-entity disambiguation, automatic surrounding-world discovery, active edit monitoring, concurrent live reads, detailed real-time readiness, empirical person scoring/ML, and quant/strategy integration. Excluding these from V1 does not excuse loss of retained source material, scope, time or material qualifications.

No production code, retained diagnostic fixture, live graph, source account, provider subscription or external system was changed in preparing this matrix. No new test or benchmark was executed; existing results above are documentary evidence only.
